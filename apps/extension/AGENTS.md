# AGENTS.md

## App Boundary

- This is the Chrome MV3 extension app, built by Vite + `@crxjs/vite-plugin` from `manifest.config.ts`.
- Popup entry is `src/popup.tsx`; routes are generated by `vite-plugin-pages` from `src/pages` and consumed through `~react-pages` in `src/App.tsx`.
- Background service worker entry is `src/background/index.ts`.
- Content scripts for element copying, translation, video sniffing, recording, and network monitoring are registered separately in `manifest.config.ts`.
- `src/content-script/index.ts` connects the top-level page to `@chrome-ninja/dev-bridge/client`; keep it independent of feature handlers.
- `pnpm dev` watches extension builds and reloads affected contexts through dev-bridge. Pass `--port` when `8787` is occupied; the same port is passed to the extension build as `VITE_CHROME_NINJA_DEV_BRIDGE_PORT`. The background uses `DEV_BRIDGE_ENABLED` to set the toolbar badge to `dev` independently of the bridge connection, and clears the badge in production builds. Development backgrounds open the toolbar popup on first connection and after client/tab reloads; production builds do not enable this behavior.
- Development bridge builds disable Rollup cache so CRXJS regenerates manifest and dynamic content-script references on every rebuild. Validate at least two consecutive rebuilds when changing the development build flow.
- Home page feature entry points form an edge-to-edge, sortable list. Cookie editor opens its webpage panel; other detailed editing workflows use modal dialogs.
- Page control is a home-list switch, not a dev-bridge command. Read `../../docs/adr/0004-page-control-without-cdp.md` before changing its boundary. `src/page-control/background.ts` connects to the local service only while the switch is on. Every action except `tab-list` requires `tabId`. `activate` focuses that tab's window and makes the tab active. `screenshot` requires `tabId`. `captureVisibleTab` can only see the window's visible tab, so a background tab is activated for the capture and the previous tab is restored. It does not use `chrome.debugger`. `navigation` with `newPage: true` opens a child of the given tab in that tab's window, records the parent-child link, and returns the new `tabId`. Turning page control off clears every link. Closing a tab clears the links rooted at that tab. Operated tabs and tabs opened by `navigation` join the single `page-control` tab group. A second group with that title is merged into it. `tab-list` returns `title`, `tabId`, `url`, and `active` for every tab in the last focused window and does not inject into pages. `history` reload uses `chrome.tabs.reload`. `history` back and forward call `history.back()` and `history.forward()` in the page; do not switch them back to `chrome.tabs.goBack` or `goForward`. Do not attach `chrome.debugger`.

## MV3 Gotchas

- `manifest.config.ts` scans `src/content-script` into `web_accessible_resources`. For separately injected modules, use CRXJS `?script` loaders with `chrome.scripting.executeScript({ files })` so their dependencies are bundled and exposed; functions passed through `func` must be self-contained.
- Default extension options live in `src/store/options.ts` (`DEFAULT_OPTIONS`); option types live in `src/types.ts`.
- `chrome.storage.local` is the source of persisted options; `src/store/options.ts` mirrors it into Jotai.

## Popup And Options UI

- Popup and options pages use Preact with `preact/compat` and `@preact/preset-vite`, plus Base UI, Jotai, React Router, Tailwind v4, and `normalize.css`.
- Base UI, `react-router-dom`, and `react-hook-form` rely on `preact/compat` compatibility.
- `pnpm install` reports missing React peer warnings for those libraries; this is expected because React runtime is intentionally not installed.
- Tailwind v4 is wired through `@tailwindcss/vite`; `src/index.css` imports theme/utilities only, so Tailwind preflight stays disabled.

## Content UI

- Applies to all webpage-injected UI, including recording and network panels, translation cards, video buttons, and copy feedback. Read `../../docs/adr/0001-content-ui-vanjs-inline-styles.md` before changing its architecture or isolation policy.
- Use `vanjs-core` and native inline `style`. Keep Preact, Tailwind, and popup/options global styles out of content UI dependencies.
- Compose business UI from shared atomic components in `src/content-ui/`; use its fixed light theme for colors, typography, spacing, radii, and layers. Keep business content, layout, Chrome messaging, and configuration subscriptions in feature modules.
- Components are functions returning native DOM nodes, composed through props and children. Drive interactive styles with events and VanJS state.
- Mount directly into webpage DOM. Do not introduce Shadow DOM, iframe isolation, or `!important`; host styles overriding content UI are an accepted boundary.
- Use the shared mounting and scope helpers. Feature views expose `dispose()`; unmounting must remove DOM and release global listeners, subscriptions, timers, and other owned resources. Repeated toggles must not accumulate mounts or listeners.
- Update locally and reuse stable nodes to preserve focus, selection, scroll positions, and panel dimensions. Preserve existing business behavior, message protocols, and frame-specific responsibilities.
- Movable, resizable panels (Cookie editor, network monitor, step recorder) use `src/content-ui/panel-geometry.ts` to load geometry before mounting, share title-bar dragging, and save only after a drag changes position or native resize changes inline dimensions and actual size. Each panel has an independent `chrome.storage.local` key (`contentUiPanelLayouts.<panel-key>`) shared across sites and tabs; restoration and dragging use the same 8px viewport margin and per-panel minimum sizes, reduced when the viewport is smaller.
- Mark every UI root with `data-chrome-ninja-ui` and exclude its clicks, input, and scroll from recording via `isContentUIEvent`. Handle propagation only where the feature needs it.
- Reuse the shared Toast for both normal copy feedback and the independently injected failure entry. Browser-restricted pages retain best-effort logging; this path does not bypass injection restrictions.

## Cookie Editor

- `src/cookie-editor/background.ts` owns the `cookie-editor` message commands, Cookie observation, and persisted disable rules. Read the Cookie editor section in `README.md` for removal attribution and recovery boundaries.
- The Popup and webpage context menu share the background's editor-open flow. `src/cookie-editor/content.ts` is injected into the top frame with a CRXJS `?script` loader and acknowledges mounting; `panel.ts` owns webpage drafts and subscriptions.
- Scope comes from the sender tab (top frame), its Cookie store, and `chrome.cookies.getPartitionKey`. Identity includes name, Domain, Path, store, and both partition key fields. Expired writes remove an exact identity; URL/name removal is insufficient.

## Browser presets

- Before changing device identities, touch emulation, or the interaction with independent UA, read `../../docs/adr/0003-browser-preset-via-cdp.md`. The Browser Presets section in `README.md` covers the workflow and tab-group lifecycle.
- Keep presets scoped to the target tab. Always replace the complete emulation settings when reusing a debugger session, and restore that tab's independent UA rule on every exit path.
- Keep the device catalog independent from the standalone UA menu. Resolve a custom preset's identity and layout from its immutable source device, and share validation between the page and background.

## Checks

- Run `pnpm --filter @chrome-ninja/extension lint` and `pnpm --filter @chrome-ninja/extension typecheck` for source edits.
- Run `pnpm --filter @chrome-ninja/extension build` when touching manifest, background, content-script, assets, or Vite config.

## Dev Debugging/Popup Debugging

- Open `chrome-extension://<id>/index.html` in a normal browser tab — that page is the extension popup, so it can be debugged like any web page (`<id>` is the extension ID from `chrome://extensions`).
