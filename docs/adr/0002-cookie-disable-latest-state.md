# Cookie 持续禁用并恢复最新状态

Cookie 编辑器将禁用建模为持久规则，而非一次移除。网站重新写入被禁用的 Cookie 时，扩展保留最新可观测内容与属性并再次移除；取消禁用恢复最新可观测且仍有效的版本，不恢复最初备份，不延长有效期，也不复活已明确识别为网站删除的 Cookie。规则在面板关闭、网页刷新及浏览器重启后保留，避免禁用效果依赖面板生命周期。

规则按名称、Domain、Path、浏览器 Cookie 存储区和完整分区身份识别 Cookie，影响共享该 Cookie 的所有标签页。不能仅按名称或页面 origin 识别，否则会混淆不同路径、分区或共享父域的 Cookie。

持续禁用使用 Cookie 变更通知，在写入后保存并移除；接受写入与移除之间的短暂窗口，不承诺在该窗口内阻断网页读取或请求携带。扩展自身执行的移除不表示网站删除，不得据此抹去恢复数据。此选择保留 Cookie 最新状态并使用现有权限，避免将规则误解为请求发送前的绝对阻断。

网站对已不存在 Cookie 的过期写入不会产生该 Cookie 的变更事件，扩展因此无法完整追踪删除意图。恢复仅依据最后实际观测到的版本及其原有效期，不推断不可观测的删除，也不增加额外网络或网页脚本拦截机制。这些限制构成持续禁用的能力边界。

Chrome 的 Cookie 变更事件不包含操作来源。网站若恰好在扩展过期写入的执行窗口内，也对同一完整身份执行过期删除，两者的事件可能相同，无法可靠归属。此窗口采用优先保留最新恢复数据的策略：通过持久化的待处理移除标记将来源不可区分的事件归为自身移除，取消禁用时可能恢复网站在该窗口内删除的 Cookie。不承诺识别此类并发删除，也不因此扩大到网络或网页脚本拦截。归属需同时具有本地标记与当前浏览器会话的有效登记，后台重建不能单凭本地残留标记恢复归属。过期写入明确失败或确认未移除目标时撤销其归属，包括已排队事件持有的归属；本地和会话记录分别清理，单侧清理失败不会阻止另一侧撤销，任一清理失败均明确报错，禁用规则与恢复数据保留以供存储恢复后重试。可明确归为网站删除的事件仍清除恢复资格；这一取舍避免把扩展实际移除的较新版本误判为网站删除而丢失恢复数据。

编辑器仅提供单条 Cookie 的取消禁用能力，不提供整批“恢复原始快照”，避免将持续追踪的最新状态覆盖为早期状态。具体面板与交互需求记录在本地需求文件中。
