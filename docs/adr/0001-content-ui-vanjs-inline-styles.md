# 网页内界面使用 VanJS 和内联样式

记录器、网络监控、划词翻译、视频操作按钮和元素复制提示统一使用 `vanjs-core` 与原生 `style` 属性，通过共享原子组件组合业务界面。样式由 TypeScript 主题值和样式函数生成，交互状态由事件与 VanJS 状态驱动，不引入名为 `inline-css` 的转换库。

网页内界面移除 Shadow DOM 和 Tailwind CSS，直接挂载到网页 DOM，也不以 iframe 替代隔离。生成的内联样式不使用 `!important`，明确接受宿主网页样式覆盖。这是本次重构选择的兼容边界，后续维护不应自行恢复强制样式隔离。

五类界面统一采用浅色主题，以白色背景、深色文字和蓝色强调色为基准，共享颜色、字号、间距与圆角。保留各业务界面的布局、位置、信息密度和现有功能行为；本次不加入深色模式、跟随系统或自定义主题。

后台消息协议、配置同步和业务流程保持现有行为。扩展弹窗与选项页保留现有技术栈；此决策仅适用于网页内界面。

公共组件位于扩展内部的 `src/content-ui/`，本次不建立独立 workspace 包。基础组件包括按钮、图标按钮、输入框、文本、表面容器与布局容器，并组合出通用面板标题、状态提示、折叠区和 Toast。主题值、基础样式和交互状态由公共组件管理；录制步骤、请求记录、翻译结果等业务内容及布局由各功能目录管理。

组件采用函数返回原生 DOM 节点的接口，通过属性和子节点组合。Chrome 消息、配置订阅、请求与业务状态由功能入口管理。业务界面提供统一的 `dispose()`，清理全局监听、订阅、计时器和 DOM；局部更新应保留输入焦点、选区与滚动位置。

五类界面的根节点统一使用 `data-chrome-ninja-ui` 标记，录制器排除其中的点击、输入和滚动。这会补齐现有翻译和视频界面的排除行为。各功能按需处理事件，不对全部界面事件统一阻止传播。

元素复制的失败提示使用独立脚本入口加载同一个公共 Toast，替换要求函数自包含的注入方式。浏览器禁止注入的页面仍记录失败，本次不增加系统通知等提示渠道。

迁移验收覆盖五类界面的现有交互、局部更新、反复开关后的资源清理与录制排除，要求 lint、类型检查和扩展构建通过。无宿主样式干扰时验证主题一致性；宿主覆盖样式属于已接受的表现，不以此为由恢复隔离或增加 `!important`。
