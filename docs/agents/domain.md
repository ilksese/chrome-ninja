# 领域文档

本仓库采用 single-context：统一维护根目录词汇表和 ADR。

## 探索代码前

- 阅读根目录的 `GLOSSARY.md`。
- 阅读 `docs/adr/` 中与当前工作范围相关的 ADR。

文件或目录不存在时静默继续，不因缺失而报告问题或建议预先创建。
词汇和决策得到明确结论后，由 `/domain-modeling` 按需创建文档。

## 文件布局

- `GLOSSARY.md`：仓库统一的领域术语。
- `docs/adr/`：仓库的架构决策记录。

## 使用词汇表中的术语

Issue 标题、重构建议、假设和测试名称涉及领域概念时，
使用 `GLOSSARY.md` 定义的术语，遵循其明确约定的用词。

所需概念尚未收录时，先检查是否引入了项目未使用的表达；
确有术语缺口时，将其记录为后续 `/domain-modeling` 的输入。

## 显式指出 ADR 冲突

建议与现有 ADR 冲突时，指出相关 ADR、冲突点以及重新讨论的理由，
再由用户决定是否调整已有决策。
